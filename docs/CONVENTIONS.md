how the codebase is put together. Where this file and the spec disagree, the spec wins; say so in
your report.

## 3. Server rules

1. **Reads**: Server Components call `lib/data/*` functions with the session client from
   `getSession()` (`lib/auth/current-user.ts`). Never the admin client for reads a user could make.
2. **Writes**: Server Actions in `server/actions/*`, each `defineAction({ name, schema, roles }, handler)`
   from `lib/action.ts`. Handlers return `ok(data)` / `fail(msg)` or throw `ActionError`. DB errors go
   through `throwIfDbError`. Side effects (email, notifications, timeline, generation) go in
   `ctx.after(label, fn, warning)` so they can never fail the save (§0.1 rule 5). Mutations call
   `ctx.audit({...})` (§0.1 rule 12).
3. **Role checks read `profiles.role`** (via `getSession`) — never `user_metadata`, never trust a role
   sent by the client (§0.1 rule 9). `lib/auth/roles.ts` has the capability table for the UI.
4. **Multi-row business transactions** (onboarding, invoice issue, receipt, credit note, status change
   with history) are **Postgres functions** called with `supabase.rpc(...)` under the user's session
   (`security invoker` unless the spec needs definer). User-facing refusals inside SQL:
   `raise exception 'USER: <plain sentence>' using errcode = 'P0001';` (`throwIfDbError` turns it into
   an ActionError).
5. **Route handlers** (`app/api/**/route.ts`) return JSON `{ ok, data | error, ref }` with the same
   contract, wrap their body in try/catch, log with `logUnexpected`, and set `Cache-Control: no-store`
   for anything user-specific.
6. **Layouts** catch their own data loads and degrade (§0.1 rule 3). Every route group has `error.tsx`.
7. **Pagination, sort, filter and search happen in SQL** (§2.3): `.range()`, `.order()`, `.ilike()`,
   `count: 'exact'`. Default page size 25 (50/100 allowed). URL search params hold the table state.
8. **Optimistic concurrency** (§13): edit forms carry the row's `updated_at`; update with
   `.eq('updated_at', loaded)`; zero rows updated → `fail("Changed by … at …. Reload to see their changes.", { code: "conflict" })`.
9. **Soft delete**: every list filters `deleted_at is null`.
10. **No caching across users** (§0.1 rule 15): no `unstable_cache`, no module-level data.
11. **Money** (§0.1 rule 7): DB `numeric(14,2)`; in TS convert to integer paise with
    `lib/domain/money.ts` before any arithmetic; display with its `formatINR`. Never float maths.
12. **Dates** (§0.1 rule 13): "today" is `todayIST()` from `lib/domain/fy.ts`; date-only facts are
    `YYYY-MM-DD` strings; display with `lib/format.ts` (`22 Oct 2026`).
13. **Employees never receive fee data** (§4.1): query `client_services_public` (not `client_services`)
    for them, and never select money columns in anything an Employee can reach.
14. **Files**: private buckets; uploads/downloads via short-lived signed URLs issued after an RLS check
    (`app/api/files/*`), 25 MB max, magic-byte MIME check (§12).

## 4. Database rules (supabase/migrations)

- Files `NNNN_snake_name.sql`, applied in filename order by `scripts/db-local.ts` and the Supabase CLI.
  Never edit an applied migration; add a new one. **Number ranges are assigned per agent** in its brief.
- Every table: `id uuid primary key default gen_random_uuid()` (unless spec says otherwise),
  `created_at`/`updated_at timestamptz not null default now()` with the shared `set_updated_at()` trigger,
  RLS **enabled**, and policies per §4.6 using the helper functions (`app_role()`, `is_partner()`,
  `is_manager_or_partner()`, `is_staff()`, `is_client()`, `my_employee_id()`, `can_see_client(cid)`,
  `can_open_whatsapp(cid)`).
- Security-definer functions: `security definer stable` where read-only, `set search_path = public, extensions`.
  Revoke execute from `anon` unless the function is public by design.
- Extensions live in schema `extensions` (citext, pg_trgm, pgcrypto); `gen_random_uuid()` is core.
- Enum values exactly as §5.1. Derived states (overdue) are computed in views, never stored.
- `app_meta.schema_version` is set by the highest migration; `EXPECTED_SCHEMA_VERSION` in `lib/env.ts`
  must match it (the integrator updates both).
- Local harness: `npm run db:reset` (needs `.env.test.local` with `LOCAL_PG_ADMIN_URL`; a local Postgres 16
  with the Supabase shim in `tests/db/shim/`). DB tests in `tests/db/*.test.ts` (`npm run test:db`).
- After schema changes run `npm run db:types` to regenerate `lib/database.types.ts`.

## 5. Client rules

- Forms: react-hook-form + `zodResolver` with the shared schema; call the action; map
  `result.fieldErrors` back with `setError`; show `result.error` in a form-level alert (with Ref);
  show `result.warnings` as warning toasts (sonner). Keep the user's input on error.
- Dialog/wizard footers are sticky and always visible at 1366×768 and 390×844 (§0.1 rule 4): use
  `components/app/form-dialog` / `components/app/wizard`; never a fixed `min-height` bigger than
  `min(560px, 68dvh)`.
- Every list/page has designed loading (skeleton shaped like the content), empty, filtered-empty and
  error states (§3.4). Use `components/app/*` patterns.
- Status is never colour alone: `StatusChip` (dot + label + hover explanation from `lib/status.ts`).

## 6. Testing

- Every pure function in `lib/domain` has Vitest tests in `tests/unit/<name>.test.ts` (§14).
- Run only your own tests while working: `npx vitest run tests/unit/<file>`.
- Typecheck: `npx tsc --noEmit -p .` (other agents may be mid-edit: judge only errors in your files).

## 7. Working alongside other agents

Several agents build in this tree at the same time. **Only create or edit files inside the paths your
brief assigns you.** If you need something from a shared file you don't own (a new UI pattern, a nav
item, a domain helper), build a local version inside your own paths, and list the request in your final
report. Don't run `npm install`, `next build` or `db:reset` against the shared `taxwise_local` database
unless your brief says so (use your own database name, e.g. `npx tsx scripts/db-local.ts reset taxwise_<you>`).
Don't commit; the integrator commits.
